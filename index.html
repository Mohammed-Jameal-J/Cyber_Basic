01 Bug Bounty ena enna?

// oru company kudukura "official permission" oda avanga website/app la bugs kandupudika

Bug Bounty nu solna, oru company (example: Google, Facebook, Zomato, Swiggy) avanga "vaanga, engala website/app la irukura security bugs-a kandupudinga, naanga paisa kudukuren" nu open ah invite pannuvanga. Ithu legal aana, permission kuduthu panra hacking — idhu than "ethical hacking" nu solluvom.

Simple ah sollanum na: neenga oru "digital lock" pota veedu (website) la, andha veedu-oda owner unnala vera door edhachum thirakalama nu check pannanum nu kekkarangale — adhukaga unnaku reward kudukuranga.

Epdi work agudhu

Company scope kudukuranga

Enna website/app test pannalam, enna panna koodathu (example: real users-oda data-a delete pannak koodathu) nu oru "scope document" kudupanga.

Neenga bug kandupudinga

Recon, scanning, manual testing panni oru vulnerability (bug) kandupudikanum — example: login page la password bypass agura maadhiri bug.

Report submit pannurathu

Clear ah bug enna, epdi reproduce pannanum, enna impact nu oru report eluthi HackerOne/Bugcrowd mூla submit pannurom.

Triage & Reward

Company-oda security team check pannitu, valid bug na, severity ku thakka bounty (money) illa hall-of-fame credit kudupanga.

Real example: 2019 la oru security researcher Facebook-oda "forgot password" flow la oru bug kandupudichaar — andha bug use pannirundha, yaaru vena oru account-oda password-a reset panniralam. Athukaga avarukku $15,000 bounty kidaichuchu. Ithu than bug bounty — real bug, real reward.

02 Penetration Testing (Pentest) ena enna?

// company neraya "engala system-a full ah test pannunga" nu hire pannura structured process

Penetration Testing nu solna, oru company neenga oda oru security firm/individual-a hire pannuvanga — "engal network/app/server-a full ah attack panni paakunga, weakness enna nu sollunga" nu. Ithu oru fixed time (example: 2 weeks) + fixed scope + contract based work.

🎯 Goal

Maximum possible vulnerabilities-a find panni, oru detailed report oda business risk explain pannurathu.

⏱️ Duration

Fixed time frame — 1 to 4 weeks usually, contract la mention pannirupanga.

💰 Payment

Bug bounty maadhiri "per-bug" illa — fixed project fee, edhukum bug kidaichalum kidaikadhalum.

📄 Output

Oru formal pentest report — executive summary + technical details + fix recommendations.

Types of Pentest

  • Black Box — outsider hacker maadhiri, edhuvum theriyama test pannurathu (real attacker scenario).
  • White Box — full source code, architecture ellam kudukuranga, deep ah test pannurathu.
  • Grey Box — konjam information kudukuranga (example: oru normal user login) — idhu than most common.

04 General Methodology (Ella testing kum common process)

// idha step by step follow pannina, edho oru random-ah click pannuradha vida results kidaikum

1. Reconnaissance (Recon)

Target pathi maximum information sekurikarathu — subdomains, open ports, technologies, employee emails. Tools: nmap, Sublist3r, Google dorking.

2. Scanning & Enumeration

Enna services run agudhu, enna versions, enna vulnerabilities exist agalam nu deep ah scan pannurathu.

3. Vulnerability Analysis

Kandupudicha info-a vachi, "idhu exploit panna mudiuma" nu analyze pannurathu — manual + automated tools.

4. Exploitation

5. Post-Exploitation

(Pentest la mattum) bug oru vaati exploit aachu na, evlo damage panna mudiyum nu check pannurathu — privilege escalation, lateral movement.

6. Reporting

Ella steps ஐயும் document panni, screenshots, impact, fix suggestion oda oru clean report kudukurathu. Idhu than mukkiyamana step — nalla report illana bug reject aagividum.

05 Networking Basics — IP, DNS, SSL/TLS, Cookies & Session

// idha puriyalana, bug bounty/pentest report padikkarathe kastapadum — networking than foundation

Hacking padikara munnadi, network epdi work agudhu nu puriyanum. Idha oru postal system nu nenachukonga — IP address ена "veedu number", DNS ена "phone book", SSL/TLS ена "sealed envelope", cookies/session ена "entry pass". Ella 4-ஐயும் keela detail ah paakalam.

🌐 IP Address — Internet-la unga "veedu number"

Ovvoru device (laptop, phone, server) internet-la connect aana udane, adhukku oru unique number kidaikum — idha IP Address nu solluvom. Example: 142.250.193.14 (Google-oda oru server IP). Postman letter deliver panna veedu number theriyanum madhiri, data packets deliver panna IP address theriyanum.

Public IP

Internet-la unga router-ku ISP kudukura address — velila irundhu unga network-a identify pannum.

Private IP

Unga home WiFi/office network-kulla mattum use aagum (example: 192.168.1.5) — internet-la direct ah visible aagadhu.

IPv4 vs IPv6

IPv4 (192.168.1.1 madhiri, 4 billion addresses mattum) run out aagudhu, so IPv6 (long hex format) vandhuchu.

Real world: Oru pentester recon phase la target company-oda IP range-a kandupudippanga (example: WHOIS lookup, ASN lookup vachi) — apparam andha range full-ஐயும் nmap vachi scan pannuvanga, enna servers active ah irukku nu.

📖 DNS — Domain Name System (Internet-oda Phone Book)

Neenga browser la google.com nu type panreenga — aana computer-ku IP address than theriyum, name theriyadhu. DNS than andha "google.com" nu sonna, adha "142.250.193.14" nu translate panni kudukum. Idhu illama na, ella website-um IP number vachi than type panna venum — evanaalum ninaikka mudiyadhu!

Real world example (Tanglish): Bug bounty recon la, "subdomain enumeration" nu oru step irukum — mail.company.com, dev.company.com, staging.company.com madhiri hidden subdomains-a DNS records vachi kandupudippanga. Neraya times staging. or dev. subdomain la weak security irukum (patch pannama vidiruvanga), athula than easy ah bug kidaikum!

🔒 SSL/TLS — Data-a "seal" panra envelope

Browser la URL https:// nu start aagi, lock icon 🔒 kanpicha, andha connection SSL/TLS encrypted nu artham. SSL (Secure Sockets Layer) pazhaya version, ippo ella site-um TLS (Transport Layer Security) use pannuranga — aana pazhaya habit-la "SSL" nu than ellarum sollுவாங்க.

Idhu illama na (plain http://), neenga type pannura password, card number ellam plain text ah network-la travel pannum — yaaru vena WiFi la "sniff" panni padikkalam. TLS irundha, andha data encrypt aagi poidum, path-la yaaru intercept pannalum "garbage" than kanpikkum.

1. TLS Handshake start

Browser matrum server "hi, enna encryption method use pannalam" nu decide pannikuranga.

2. Certificate verify

Server-oda SSL certificate (oru trusted authority, example: Let's Encrypt, DigiCert kudutha) check pannuranga — idhu fake site illa nu confirm pannurathukku.

3. Session key create

Rendu side-um sேrndhu oru temporary "secret key" create pannikuranga, adha vachi data encrypt/decrypt pannuvanga.

4. Encrypted data transfer

Ippo ella data-um andha key vachi encrypt aagi than travel pannum — HTTPS lock icon appo than varum.

Pentest angle: Weak/expired SSL certificate, self-signed cert, illa old TLS version (TLS 1.0/1.1) use pannura server-a kandupudichaa, adhu oru finding — "SSL Misconfiguration" nu report pannuvanga. Tool: sslscan target.com or testssl.sh target.com.

🍪 Cookies & Session — "Unnaku already login pannirukka" nu website epdi ninaikkudhu

HTTP protocol "stateless" — adhu artham, ஒவ்வொரு request-ஐயும் website "puthusa" nu than treat pannum, munnadi request-a "nyabagam" vechukadhu. So login panna udane, "neenga login pannitinga" nu website nyabagam vechikka, cookies matrum session use pannuranga.

🍪 Cookie

Server oru small text data unga browser-la store pannum — adhula oru unique "session ID" irukum. Ovvoru request-um andha cookie automatic ah attach aagi poidum, so server unga-va "recognize" pannikkum.

🎫 Session

Server side-la, andha session ID-ku corresponding "neenga yaaru, login pannirukinga" nu data store pannirukum. Cookie ена "ticket number", session ена server-la irukura "ticket details".

Real world example (Tanglish): "Session Hijacking" nu oru common bug — attacker vera vazhi (example: XSS bug, illa unsecured WiFi la sniffing) unga session cookie-a steal pannitanga na, avanga unga password theriyaamale, andha cookie-a use panni unga account-a "impersonate" panniralam! Athanala than banking sites la HttpOnly, Secure, SameSite madhiri cookie flags mandatory ah vekkuranga — idhu illana bug bounty report la "Missing Secure Cookie Flags" nu finding varum.

06 Nmap — Network Mapper

// recon phase la first tool ellarum use pannurathu

Nmap (Network Mapper) oru free, open-source tool — target IP/domain la enna ports open ah irukku, enna service run agudhu, enna OS use pannuranga nu kandupudika use pannurom. Idha oru "veedu-oda ella doors and windows-a check panra" tool nu nenachukonga — edhu locked, edhu open nu.

Ithu epdi work agudhu

Nmap target machine ku packets anupi, response-a analyze pannum. Ports open na response oru maadhiri varum, closed na vera maadhiri varum, filtered (firewall irukku) na response vera maadhiri irukum. Idha vachi nmap decide pannum port status enna nu.

Yen ellarum use pannuranga

  • Free & open source — evanachum use pannalam
  • Fast ah oru network full ah scan panna mudiyum
  • Service version, OS fingerprinting, vulnerability scripts (NSE) support pannum
  • Industry standard — companies, CTFs, real pentests ella la use aagum

Real world example

Oru pentester oru company-oda server IP-a scan panna, port 21 (FTP) open ah irundhuchu, aana andha FTP server "anonymous login" allow pannitu irundhuchu — yaaru vendalum login pannalam. Idha nmap first step la kandupudichi, adhukaparam manual ah exploit pannuranga. Idhu real bug bounty reports la common finding.

Common Nmap commands

# Basic scan - top 1000 ports check pannum
nmap 192.168.1.10

# Scan type -sV : service/version detect pannum
nmap -sV target.com

# -sC : default safe scripts run pannum (vulnerability hints)
nmap -sC -sV target.com

# -p- : ELLA 65535 ports um scan pannum (full scan)
nmap -p- target.com

# -O : Operating System detect panna try pannum
nmap -O target.com

# -A : aggressive scan (OS + version + scripts + traceroute)
nmap -A target.com
Nyabagam vachikonga: Neenga permission illama edhavadhu IP/domain-a scan panna koodathu — idhu illegal. Practice panna TryHackMe, HackTheBox, DVWA maadhiri legal practice labs use pannunga.

🔓 Hashcat

// world-la fastest password recovery tool nu solluvanga, GPU power use pannum

Hashcat oru advanced password cracking tool — idhu oru "hash" (password oda encrypted/scrambled version) edukuthu, adha crack panna try pannum. Idhu GPU (graphics card) use panni super fast ah run agum, athanala millions of passwords per second try panna mudiyum.

Epdi work agudhu

Neenga oru website hack pannitinga na (legal ah, pentest la), andha database la passwords "plain text" la illama, "hash" (example: MD5, SHA256) form la irukum. Andha hash-a direct ah padikka mudiyadhu — so hashcat guess panna try pannum: ஒரு word edukum → hash pannum → database hash oda compare pannum → match aana andha than password.

Rendu main modes

-a 0 (Dictionary Mode)

Oru pre-made wordlist file (example: rockyou.txt la 14 million common passwords irukum) edukum, ovvoru word ah hash panni compare pannum. Fast & effective na common passwords-ku.

-a 3 (Mask/Brute-force Mode)

Character set define pannitu (example: 8 characters, lowercase+numbers) ella combination um systematically try pannum. Slow but guaranteed — wordlist la illatha unique password-um kandupudikkalam.

# Dictionary attack - MD5 hash crack
hashcat -a 0 -m 0 hash.txt rockyou.txt

# Mask attack - 8 char, lowercase+digit combination
hashcat -a 3 -m 0 hash.txt ?l?l?l?l?l?l?d?d
Real world: 2012 la LinkedIn oda 6.5 million password hashes leak aachu. Security researchers hashcat use panni, weak passwords ("123456", "linkedin") edho poi kandupudichanga minutes kulla — athanala than companies ippo "salting" + strong hashing algorithms (bcrypt) use pannuranga.

🗝️ John the Ripper (JtR)

// oldest & most trusted password cracker, CPU based, beginner friendly

John the Ripper oru classic password cracking tool — 1996 la irundhu irukku. Hashcat GPU use pannuchu na, John mainly CPU use pannum (aana GPU support-um irukku ippo). Idhu especially Linux/Unix password files (/etc/shadow) crack panna popular ah use aagum.

Rendu main modes

--wordlist

Hashcat-oda dictionary mode maadhiri than — oru wordlist file kudukurom, andha la irundhu try pannum.

--incremental

Idhu than John-oda brute-force mode — every possible character combination-a systematic ah generate panni try pannum, wordlist edhuvum illama.

# Wordlist mode
john --wordlist=rockyou.txt hash.txt

# Incremental (brute-force) mode
john --incremental hash.txt

# Cracked passwords paakanum na
john --show hash.txt
Real world: CTF (Capture The Flag) competitions la, oru Linux machine capture pannina udane, adhoda /etc/shadow file-a copy panni John the Ripper vachi crack panuranga — idhu ethical hacking training la super common exercise.

📄 pdfcrack

// specifically password-protected PDF files crack panna use aagum small tool

pdfcrack oru specialized tool — idhu ella hash types-um handle pannadhu, PDF file password protection mattum target pannum. Neenga oru encrypted PDF (open panna password kekkum) file paartha, idha use panni crack panna try pannalam.

-w flag (Wordlist)

Oru wordlist file kudukurom, adhula irundhu ovvoru word ah try pannum PDF password ah.

-c flag (Character set)

Brute-force mode — character set specify pannurom (example: numbers mattum, or lowercase+numbers), ella combination-um try pannum.

# Wordlist based attack
pdfcrack -w rockyou.txt secret.pdf

# Brute-force with custom charset (numbers only, ex: 4 digit pin)
pdfcrack -c 0123456789 -n 4 -m 4 secret.pdf
Real world: Legal forensics investigations la, oru suspect-oda laptop la password-protected PDF (financial records) kidaicha, law enforcement pdfcrack maadhiri tools use panni (proper legal authorization oda) andha file-a access pannuranga.

⚙️ Crunch

// itha oru cracker nu ninaikkadinga — idhu oru wordlist GENERATOR

Crunch vera tools madhiri password crack pannadhu — idhu oru custom wordlist generator. Neenga rules define pannurathu (character set, length, pattern), Crunch andha rules ku thakka ella possible combinations-um oru wordlist ah real-time generate pannikodukum. Andha wordlist-a apparam hashcat/John kitta feed pannalam.

Yen use pannuranga

Suppose neenga therinjikitinga oru company password policy "8 characters, must include company name + 4 digits" nu — andha specific pattern ku thakka Crunch oru custom wordlist generate pannikodukum, generic rockyou.txt vida idhu far more targeted & effective aagum.

# Pattern based: company name + 4 digit (@ = lowercase, % = number)
crunch 8 8 -t infy%%%% -o custom.txt
Real world: Pentest la oru client sonnanga "engal WiFi password format employee_id + birth year" nu — andha exact pattern ku Crunch use panni custom wordlist generate panni, minutes kulla WiFi password crack pannuranga (generic wordlist use pannirundha days aagum).

18 Cybersecurity Fundamentals — Basic Knowledge Ella Beginner-um Therinjikkanum

🔺 CIA Triad — cybersecurity oda "goal" enna

Cybersecurity-oda ella work-um, intha 3 goals achieve panna than — CIA Triad nu solluvom (spy agency illa!):

🔒 Confidentiality

Data-a authorized aana people mattum paakanum — unauthorized access thadukanum (example: encryption).

✅ Integrity

⚡ Availability

System/data evallovendra time-um authorized users-ku access aaganum — down aagakoodathu (example: DDoS protection, backups).
